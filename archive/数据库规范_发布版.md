# TF 叶栅设计与 MISES 数据库规范 v0.0

## 1. 数据实体

数据库由设计、工况和气动点组成。一个设计对应多个工况；一个工况对应一个或多个气动点。若对入流角进行扫掠并提取特征点，可增加特征点表。各表使用稳定标识符关联，不依赖文件排列顺序。

| 文件 | 一行代表 | 主键 |
|---|---|---|
| `designs.csv` | 一个叶型或叶栅设计 | `design_id` |
| `cases.csv` | 一个求解工况，包含成功和失败状态 | `case_id` |
| `operating_points.csv` | 一个有效气动计算点 | `point_id` |
| `characteristic_points.csv` | 一个扫掠特征点；按需交付 | `case_id,point_type` |

`cases.design_id` 引用 `designs.design_id`；`operating_points.case_id` 和 `characteristic_points.case_id` 引用 `cases.case_id`。失败工况在 `cases.csv` 中保留状态及原因，不生成虚构的输出点。为后续机器学习模型的训练而连接或展开的表可从这些基础表生成。

## 2. 通用文件和单位规则

CSV 使用 UTF-8、首行字段名、小数点 `.`。缺失值为空单元格；不使用 `0` 或 `-1` 代替缺失。布尔值用 `true/false`。角度以 `deg`、物理长度以 `m`、温度以 `K`、压力以 `Pa` 记录；无量纲字段注明归一化基准。标识符非空且唯一；外键必须可解析。每个字段的定义、单位、来源和可用条件由《数据库字段与物理量词典》规定。

## 3. 设计表 designs.csv

`designs.csv` 主要包括叶型设计参数信息如弦长`chord_m`、稠度`solidity` 等。注意其必须包含 `design_id`。。该表可加入参数化方法或几何表示、可重建的几何文件或几何数据、几何有效性 `valid`。使用边界层厚度等 MISES 无量纲量时，必须提供 `mises_reference_length_m`。

参数化设计中包括 `x_t`、`t_max_over_c`、`x_c`、`camber_max_over_c`、`betac_le_deg`、`betac_te_deg`、`gamma_deg`、`le_axis_ratio`、`te_thickness_over_c`。`betac_le_deg` 和 `betac_te_deg` 是弯度线前后缘方向角，`gamma_deg` 是安装角；必须在几何约定中给出角度正方向。`sampling_method`、`sample_index`、`baseline`是可选的采样信息和基线叶型标识。

## 4. 工况表 cases.csv

`cases.csv` 记录仿真所得入口 Mach `M1`、Reynolds 数或计算所需状态、入口总温/总压、湍流度、入口角、出口约束、适用的流道/旋转设置、求解状态和失败原因。每个工况用 `mach_control_mode` 指明入口 Mach 的控制方式；实际 Mach 应与该方式相符。求解设置中不适用的字段留空。

给定进口气流角度求解时，`inlet_angle_mode` 取 `single` 或 `sweep`。单点计算记录一个入口角。扫掠计算另记录扫掠中心定义、偏移序列、角度正方向及是否自适应扩展。不同工况可采用不同中心定义。

## 5. 气动点和特征点

`operating_points.csv` 至少记录实际入口/出口 Mach、入口/出口角、损失指标、扩散指标和求解状态；速度、边界层与尾迹量按可用情况填写。应区分求解器直接输出、扩展程序输出和数据库计算字段。不同版本没有输出的量留空并记录可用性，不用估计值伪装成原始结果。

`characteristic_points.csv` 仅适用于已定义扫掠及提取方法的工况。每个特征点记录 `point_type`、损失指标、特征位置、是否插值、目标损失和提取状态。双倍损失未达到时可标为 `boundary_limited`；扫描边界点不能标为已达到的交点。

## 6. 质量检查与发布

发布前检查主键唯一、外键完整、数值有限、单位和角度约定一致、几何与参考长度为正、工况控制条件一致、输出状态可追溯。`Wmax` 等存在提取质量问题的字段必须带质量状态，不能无条件用于物理模型。数据包附简短元数据，列明字段版本、计算方法、软件版本、生成日期与表行数。

MISES 物理输出量详见《MISES 输出量与解析说明》；全部字段释义见《数据库字段与物理量词典》。
