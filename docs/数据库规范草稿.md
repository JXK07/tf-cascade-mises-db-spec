# 叶栅设计与 MISES 数据库规范（内部版草稿 v0.3）

## 1. 数据模型

数据库以**设计**、**求解工况**、**气动计算点**为基本实体；在执行入流角扫掠时可增加**特征点**。一个设计可对应多个工况，一个工况可对应一个或多个气动点。所有表必须保留稳定的 `design_id`、`case_id` 和清晰的单位。

## 2. 推荐的最小交付文件

| 文件 | 粒度和主键 | 内容 |
|---|---|---|
| `designs.csv` | 一个设计；`design_id` | 几何设计输入、有效性 |
| `cases.csv` | 一个实际求解工况；`case_id`，且 `design_id` 外键 | 最终采用的 MISES 边界条件、收敛状态和可选的结果位置 |
| `operating_points.csv` | 一个有效气动点；`point_id`，且 `case_id` 外键 | 求解输出；单点计算也是一行，扫掠时每个入流角一行 |
| `characteristic_points.csv` | 一个特征点；`case_id,point_type` | **可选**，仅在扫掠并提取最小损失/双倍损失点时交付 |

`design_runs.csv` 属于执行日志，`aero_runs_all.csv` 属于失败审计，不纳入最小交付；需要审计时可另存。`ml_polar_points.csv`、`ml_characteristics_long.csv` 是连接后的冗余派生表，无需保存为规范核心表；建模时从主表生成。宽表也只作为特定模型的导出视图。不得因精简交付而丢失失败工况的状态：`cases.csv` 应包含计划执行但失败的工况，失败时输出点为空。

CSV 用 UTF-8、首行字段名、小数点 `.`、空单元格表示缺失；不以 `0`、`-1` 代替缺失。布尔值统一 `true/false`。数值字段记录量纲，角度统一 `deg`、长度统一 `m`，无量纲量在字段字典注明。主键必须唯一，外键必须可解析。原始求解文件可另附，不属于这四张表。

## 3. 设计参数

必需：`design_id`、参数化方法、叶型几何或可重建几何的文件路径、实际弦长 `chord_m`、`solidity`、几何有效性 `valid`。参数化方法不同时可扩展专用参数；不存在的参数留空，不强制所有设计采用 BP3333。

| 规范字段 | 含义 | 属性 |
|---|---|---|
| `x_t`, `t_max_over_c`, `x_c`, `camber_max_over_c` | 最大厚度和弯度位置/幅值，按弦长归一化 | 参数化叶型可选 |
| `betac_le_deg`, `betac_te_deg` | 前缘、后缘**弯度线方向角**；具体正方向应写入几何约定 | 参数化叶型可选 |
| `gamma_deg` | 叶型安装角 | 可选；不得与前缘形状角混同 |
| `le_axis_ratio`, `te_thickness_over_c` | 前缘椭圆轴比、尾缘厚度比 | 可选 |
| `section_id`, `span_fraction`, `sampling_method`, `sample_index` | 截面和采样信息 | **全部可选**；独立叶栅或非采样数据无需填写 |
| `mises_reference_length_m` | MISES 无量纲量的参考长度 | 使用相关输出时必需 |

## 4. MISES 边界条件与求解方式

`cases.csv` 应记录**最终实际使用**的入口 `M1`、入口总温/总压、Reynolds 数或其计算所需状态、湍流度、入口角/等价 `Sinl`、出口约束、流道/旋转设置、参考长度及收敛状态。输入控制方式可选：固定入口 Mach、固定其他流动量，或从目标设计状态求解；用 `mach_control_mode` 标识。固定 Mach 不是所有数据库的必备条件。通用数据库的 `M1` 是最终施加并验证的工况值。

`inlet_angle_mode` 可为 `single` 或 `sweep`。单点计算保存一个实际入口角；扫掠计算还需保存扫掠中心、偏移序列、是否自适应扩展和角度约定。`geometry_zero_incidence` 只是现有数据采用的中心定义：以几何零攻角为中心改变入流角，不是通用默认值。不同工况可以使用不同中心模式或完全不扫掠。

`tsrat`、`stream_rotrel`、出口约束等仅在相应 MISES 模式使用时填写。其物理定义和输出量见《MISES 输出量与解析说明》，所有字段见《数据库字段与物理量词典》。

## 5. 输出和质量规则

每个 `operating_points.csv` 记录实际 `M1`、`M2`、入口/出口角、损失、扩散、速度及可获得的边界层/尾迹量。区分求解器原始值、改进 polar 程序新增值和数据库派生值；字段字典必须给出来源和单位。特别是 `Wmax` 仍有待核查，不能把它作为无条件可信的物理吸力面最大速度。

若生成 `characteristic_points.csv`，最小损失点应注明损失指标（例如 `omega`）和插值状态；双倍损失点应注明目标值和 `reached`/`boundary_limited` 状态。边界受限扫描端点不能标成真实双倍损失交点。未收敛和缺失数据保留状态及原因，不填入伪数值。

发布数据前至少检查：主键唯一、外键完整、数值有限、长度和温度为正、角度/单位一致、实际工况与控制模式一致、输出质量状态可追溯。版本信息可用简短的元数据文件记录字段版本及生成方法，不要求固定配置文件格式，也不要求每次边界条件调整都建立新的 campaign。

## 6. 示例与旧库映射

`examples/` 是按本规范重排的精简示例，使用同一实际设计和 Mach 0.2 工况；示例中的 `betac_le_deg`/`betac_te_deg` 留空，因为旧字段不能无推导地改名。原数据库文件保持不变。旧库 `design_features.csv` → `designs.csv`，`aero_runs_all.csv` 的最终工况状态 → `cases.csv`，`polar_operating_points.csv` → `operating_points.csv`，`characteristic_points.csv` → 可选特征表。旧运行和 ML 合并表可独立归档或按需生成。

## 7. 固定 Mach 旧库的迁移说明

旧 `requested_M1` 是任务调度目标，`Minl_requested_in_ises` 是写入 ISES 的入口 Mach，`actual_M1_min/max` 是扫掠后各点实际入口 Mach 的范围，`fixed_M1_ok` 是一致性检查。当前固定 Mach 流程中前两者通常相同，但概念不同；新核心 `cases.M1` 采用最终施加并验证的值，原字段留作审计。

旧 `reference_M1_for_Re` 仅是相似缩放 Reynolds 数的基准 Mach，不是额外求解边界条件。只有使用这种缩放方法才保留它。旧 `polar_center_mode=geometry_zero_incidence` 表示以几何零攻角为扫掠中心，不应强加给单点计算。
